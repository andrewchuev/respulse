ResPulse

Systems-Grade Synthetic Monitoring. Engineered for SREs.

ResPulse is a synthetic uptime monitoring and observability platform built in Rust. It probes HTTP/S endpoints, TCP ports and TLS certificates, watches cron jobs and workers with heartbeats, and sends alerts to Telegram, Slack, Discord and custom webhooks. Incident timelines, post-mortems and public status pages are built in.

Frequently asked questions

How does ResPulse achieve zero garbage collection pauses?

Unlike NodeJS or Python-based monitoring tools that suffer from periodic garbage collection (GC) freezes causing false latency spikes, ResPulse is built in Rust. Rust uses deterministic compile-time memory management (RAII), so there are no GC pauses to disturb probe scheduling.

Can I self-host ResPulse completely inside an isolated private VPC?

Yes! ResPulse is 100% containerized with Docker Compose. It requires only PostgreSQL and a reverse proxy (like the included Caddy 2 setup). It can run entirely within your private subnet to monitor internal databases, Kubernetes pods, and VPC endpoints without egress access.

How does push heartbeat (dead man's switch) work for cron jobs?

When you create a Heartbeat monitor, ResPulse generates a unique cryptographic webhook URL or slug URL. You can signal task start (/start), explicit failures (/fail), pass shell exit codes (/0, /1), attach full STDERR logs, and use standard 5-field cron expressions with IANA timezones. If an expected ping is missed or execution times out, an incident is immediately declared.

Does ResPulse export metrics to Prometheus and Grafana?

Yes! ResPulse provides a standard Prometheus metrics exporter endpoint at /api/metrics and /metrics, exposing gauges for monitor statuses, probe latencies, heartbeat execution durations, and ongoing incidents for instant Grafana scraping.

Which alert delivery channels are currently supported?

ResPulse natively supports Telegram Bot API, Discord Rich Embed Webhooks, Slack Incoming Webhooks, and Custom JSON Webhooks with granular tag-based alert routing (filter_tags) to direct notifications to specific on-call squads.

How does Role-Based Access Control (RBAC) enforce security?

ResPulse implements a 4-tier security model: Owner (full control & org deletion), Admin (monitor & team management), Engineer (monitor CRUD, test probes & post-mortems), and Viewer (read-only dashboards). All mutations are strictly validated on the Axum backend and return 403 Forbidden for unauthorized roles.
